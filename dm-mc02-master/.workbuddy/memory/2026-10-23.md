# 2026-10-23

## 修复：2 号电机上电"抽一下"
- 现象：6 台版（CAN1 三台 + CAN2 三台，位置轨迹来回摆）下，2 号电机上电瞬间会猛抽一下。
- 根因：**该电机上电启动比另外两台慢**（此前就观察到"2 号指示灯变绿比别人慢"）。主任务在启动后 300ms 就开始探测，每台只发 20 帧（约 20ms），慢启动的那台还没回话 → `f_pos` 保持 memset 后的 0 → `s_target = 0`。等它起来后，收到的第一个位置命令就是"去 0 位置"，于是猛抽。
- 修复（`App/dm_ctrl_task.c`，编译通过 `Code=79594 / RO=19242 / ZI=39928`）：
  - 新增 `s_init_done[]` 标志与 `traj_init(i, pos)` 辅助函数（统一做起点设置 + 摆幅收窄）。
  - 探测阶段：`online` 的才 `traj_init`；没回话的标记为"未初始化"。
  - 主循环：未初始化的电机**只发零刚度帧（kp=kd=tau=0）问反馈，绝不下发位置命令**；一旦收到反馈，立即用它此刻的真实位置初始化轨迹，然后才进入摆动。
  - 效果：慢启动的电机起来后原地起步，不再朝 0 位置甩。
- 通用教训：**任何时候都不能拿"默认 0"当电机的初始位置**；位置类的目标值必须来自真实反馈，否则就是一次全速冲零。

## 懒初始化仍抽 → 改为"等全部就绪再使能"
- 用户反馈：加了懒初始化后 2 号仍抽一下。
- 推断：不只是"目标为 0"，更可能是**使能帧落在慢启动电机的初始化窗口里**——电机被使能时按内部残留的旧指令动了一下。
- 改动（编译通过 `Code=79786 / RO=19266 / ZI=39928`）：
  1. 探测后新增"等所有电机回话"阶段：最多 300 次 × 10ms（约 3 秒），未就绪的持续发零刚度帧询问，一旦回话立即 `traj_init`。
  2. **只使能已初始化的电机**；没回话的不使能（避免带着残留指令启动）。
  3. 主循环里迟到的电机：`traj_init` → `dm_motor_enable` → 立刻压一帧零刚度占住指令，下一轮才走轨迹。
- 待用户回答的关键判据：**抽搐发生在拨通 24V 的瞬间（MCU 尚未启动），还是 1~2 秒后固件开始发帧时？** 若为瞬间，则与固件无关，属电机内部上电自检/电源冲击。

## 2 号电机不动 → 摆幅塌缩 bug
- 现象：烧录"等全部就绪再使能"版本后，2 号电机完全不动。
- 根因（自查发现）：`traj_init()` 原来按起始位置**收窄摆幅**：
  `if (pos + amp > 11.5) amp = 11.5 - pos;`
  若该电机恰好停在接近 ±11.5 rad 的位置，摆幅被压到 `0.2 rad`（约 11°）——视觉上就是"不转"。若 pos > 11.5 还会算出负值再被钳到 0.2。
- 修复：改为**摆动中心内移、摆幅始终取满**——
  `c = clamp(pos, -11.5+amp, 11.5-amp)`，`s_target` 取离当前位置最近的窗口端点，避免起步跳变。
- 编译通过，`MC02_firmware.hex` 279338 字节。
- 教训：限幅时优先移动"中心/偏置"，而不是压缩"幅值"；压缩幅值会把运动悄悄变成几乎为零。

## 关键线索：3 台比 6 台抽得更厉害 → 证实"电机未启动完就被探测"
- 用户反馈：退回 3 台后"抽得更厉害了"。
- 推理：3 台版探测阶段比 6 台版短约 60ms → 使能更早到来 → 更容易落在电机上电自检窗口内 → 更严重。**抽动的根因是探测时电机尚未就绪、不回话，起始位置被记成 0**。
- 改动（一行）：`osDelay(300)` → **`osDelay(1500)`**，给电机足够启动时间再开始探测。
  - 选择这个方案而不是"懒初始化/等全部就绪"，是因为它**不引入任何门控**，不可能造成"某台永久不动"（前面已经踩过）。
- 若仍抽，下一步把等待加到 2500ms；或接 USB-TTL 看串口哪台 `online=0`。
- 编译通过，`MC02_firmware.hex` 278242 字节。

## 决定性证据：2 号红灯变绿比另外两台慢 3~4 秒
- 用户观察到 2 号电机从红灯变绿灯（=被使能）比另外两台**晚 3~4 秒** → 该电机上电就绪确实慢 3~4 秒，之前的 1.5 秒等待根本不够。
- 这也解释了"3 台比 6 台抽得更厉害"：台数少 → 探测总时长短 → 使能更早 → 更容易撞进它未就绪的窗口。
- 方案：改为**探测重试**（不是门控）——哪台没回话就 `osDelay(2000)` 后再问，最多 4 轮（≤8 秒）。
  - 正常情况第一轮就 `all_done` 直接跳出，启动速度不受影响。
  - **4 轮后无论是否回话，一律 `traj_init` + 照常全部使能**，因此绝不会复现"某台永久不动"的问题（这是上次踩的坑）。
- 编译通过：`Code=79530 / RO=19210 / ZI=39672`。
- 若此版仍抽，则"启动时机"这条假设被推翻，需转向查该电机硬件/固件差异。

## ✅ 根因确认：2 号电机的连接线不良
- 用户自行排查得出结论：**2 号电机那根连接线有问题**（换线/对调后现象消失）。
- 这一条同时解释了今天所有异常：
  - 上电就绪比另外两台慢 3~4 秒（供电不稳 → 启动慢/反复重启）；
  - 上电"抽一下"（电压跌落或启动过程被打断）；
  - "3 台比 6 台抽得更厉害"（探测时序更早，更容易撞进它的异常窗口）。
- 与 10-14 排查清单里的头号嫌疑「XT30(2+2) 细针接触不良」完全吻合——当时没查实，今天以另一种症状复现。
- 处理建议：换一根 XT30(2+2) 线；检查插针是否缩针/氧化；插到底听"咔"；分线板那一路也换个口试。
- 固件保持"探测重试"版（`Code=79530`）：线正常时第一轮即通过、无额外开销；线不良时也能容错，**不必回退**。
