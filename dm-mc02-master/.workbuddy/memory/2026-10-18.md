## CAN 打通 + 电机「抖一下就停」判读
- 用户 10-18 用 DMTool 直驱电机（COM8 / 921600 / USB模式=CAN / CAN ID=1 / MST ID=0x11）成功：发送 2,645,912 条、接收 2,643,844 条，FPS≈1906，反馈双向通畅 → 持续 8 天的「电机从不回帧」问题已解决。
- 截图参数：MIT 模式，位置=5 rad、速度=0、KP=50、KD=0.35、转矩=0、电机已使能；反馈 Position=4.999428 rad、Velocity=-0.0073、Torque=0.0024；T_mos=28℃ / T_rotor=32℃。
- 手工解码 CAN 帧 `B3 32 7F F1 99 11 E7 FF`：pos=4.998 rad、vel=0、kp=49.94、kd=0.349、tau=0 → 与界面填写值完全吻合；实际位置误差仅 0.0014 rad（0.08°）。
- 结论：电机在正常做位置闭环，不是故障。「抖一下」= 一步跳到位 + kp 偏高/kd 偏低的过冲（图上约 0.018 rad）；「停了」= 位置模式到位即停，不会连续转。
- 调参建议：kp 降到 ~25、kd 提到 1.0~1.5；想连续转改用速度模式，或位置 5↔3 交替。
- 待确认：MC02 是否仍上电挂在 CAN1 上（两个主站同发会互相顶帧）。

## 第二台电机：MST_ID = 0 是根因
- 第二台（同型号 DM4310）参数读取成功，规格与第一台几乎一致：Rs 619.235mΩ / Ls 156.931µH / 磁链 0.00466937 Wb / 极对数 14 / 减速比 10 → 电机本体正常。
- 致命差异：**Master ID（MST_ID，RID 7）= `0x0`**，第一台是 `0x11`。反馈帧全部发往 CAN ID `0x00`，而 DMTool 监听 0x11、MC02 期待 0x11 → 双方都收不到。这是本台「没数据」的根因。
- 另：CAN Timeout（RID 9）= 0；CAN ID = 0x1（与第一台同号，同总线会撞）。
- 写参数报 `参数同步失败 [read_before]: start failed: read_param` 的原因：用户先发了 `m` 进 Motor Mode；DM 参数读写仅在上电待机态有效。
- 寄存器表已核实（DMTool 手册 P22-23）：7 MST_ID / 8 ESC_ID / 9 TIMEOUT / 10 CTRL_MODE / 35 can_br；RID 7-10、13-16、35-36 为 uint32，其余 float。
- 参数读写帧：对 CAN `0x7FF` 发 `[id_lo, id_hi, 0x33(读)/0x55(写), RID, 4字节值LE]`；应答 16B 帧 `cmd=0x11`、`data[2]=0x33/0x55`、`data[3]=RID`、`data[4:8]=值`。
- `dm_serial.py` 已扩展 `params` / `fix` 子命令，绕开 DMTool 的 read_before 流程；仍因 DMTool 占用 COM8 而阻塞。

## 第二台电机续：写参数连续失败的真正原因（16:53）
- 截图：CAN ID 被填成 `0x2`、Master ID 填 `0x12`，写参数仍报 `参数同步失败 [read_before]: start failed: read_param`；**FPS = 0.0**，发送/接收计数几乎不动 → 当前链路毫无回应。
- 关键判断：上一张图（CAN ID=`1`）时「读参数」其实是**成功**的（619.235mΩ 属第二台电机真实值），说明 ID=1 时链路是通的，写失败只因电机仍在 Motor Mode；这张图把 CAN ID 填成 2，而电机实际仍是 1 → DMTool 用 2 找不到电机 → 连 `read_param` 都起不来。等于在原有问题上叠加了 ID 错配。
- 改 CAN ID 存在「先有鸡先有蛋」：写 ID 的帧必须发往**旧** ID、值里放**新** ID，DMTool 输入框无法表达这种组合，所以用 DMTool 改 CAN ID 基本写不进去；只能脚本发 `[old_lo, old_hi, 0x55, 8, new...]`。
- 结论建议：只用一台时 **CAN ID 保持 1 不动**，只把 Master ID 写成 0x11；且必须先**断电重启**退出 Motor Mode。

## 17:10 断电重启后的开机打印（关键证据）
- 串口页完整刷出开机横幅：`CAN Error 1` / `DMBOT Motor Driver--V4.0` / FW 7020 / DM4310 24V / Sub 001 / Rs 619.2349m / Ls 156.9305uH / f 0.0047 / V_BUS 22.2979 / **CAN ID: 0x001** / **MASTER ID: 0x000** / CAN Baud 1.00Mbps / Control Mode MIT。
- 结论：**串口链路完好**（开机打印能收到）、**CAN ID 没被改成 2**（仍为 1）、**MASTER ID 仍是 0**。
- 重要纠正：UART 模式下 `接收` 计数（3377996）根本不涨，即使 16:46 读参数成功时也是这个数 → 该计数只统计 CAN 帧，不能当作「串口死了」的证据。先前两轮据此判断链路静默是错的。
- 因此 16:46 读参数成功说明 DMTool 能处理 MST_ID=0 的响应；写参数失败更可能是 **UART 模式下写参数受限**（手册原话：串口未读出的参数不会通过串口写入，需用 CAN 读写）。
- 待试：① 切 USB模式到 CAN 后写参数；② 关掉 DMTool 用 dm_serial.py 直接发写帧（read_param 不校验 CAN ID，MST_ID=0 卡不住）。
- 另记：开机横幅首行 `CAN Error 1` 暂未解释，待 ID 修好后复查。
