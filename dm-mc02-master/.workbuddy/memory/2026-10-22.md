# 2026-10-22

## 重要更正：分线板不是纯配电板
- 之前（10-19）根据一张照片判断「绿色分线板 = XT30 一拖六纯配电板」，**判断错误**。
- 用户描述的实际接口：**1 个电源输入 + 1 个 XT30（可接单片机）+ 2 个 CAN 接口 + 6 个 XT30(2+2)（可接电机）**。
- 也就是说这是一块「6 路电机配电 + CAN 分配」板：每路 XT30(2+2) 出 24V + CAN，另有两个 CAN 口回主控板。
- **影响**：电机电流可以完全不走主控板，之前担心的「输出1/输出2 每路 5A、3 台就贴边」的瓶颈**不复存在**；6 台的供电问题由分线板解决。
- **待确认的关键点**：分线板的 2 个 CAN 口是「同一条总线的两个出口」还是「分开的两条总线（3+3 分组）」。这决定固件要单总线（6 台需降到 250Hz）还是双总线（各 3 台 @500Hz）。
  - 判定方法：万用表蜂鸣档量 CAN 口① 的 H 与 CAN 口② 的 H —— 响=同一总线；不响=两条独立总线。
- 接线方案（若为双总线）：电池→分线板电源口；分线板 XT30→主控板 VCC_IN；CAN口①→主控板 CAN1 座 P2；CAN口②→CAN2 座 P3；6 个 2+2 口→6 台电机。主控板输出1/输出2 不再接电机。
- **用户已确认：分线板两边的 CAN 是分开走线的（两条独立总线）** → 6 台按 3+3 分组，CAN1 侧三台、CAN2 侧三台，各 500Hz、各 33%，即 `hfdcan1` ×3 + `hfdcan2` ×3 的配置，无需降频。
- 拓扑结论：**6 个 XT30(2+2) 口一台接一个**，不要每边只用 1 个口再菊花链。两种接法电气上都是并联节点（CAN 是总线），信号层差异小；但独立接法电流均摊、故障隔离好、排查容易，且**用线数量与菊花链完全相同**（3 台各接一口=3 根；串 3 台也是 3 根），所以没有理由选菊花链。

## 根因：配 3 台但只接 1 台 → CAN BUS-OFF
- 现象：力矩固件（配置 3 台）实际只接 1 台，5 次复位测试：前 4 次电机完全没反应，第 5 次转一会就停；而上一版「锁定」固件（当时 3 台全接）正常。
- 根因：`Core/Src/fdcan.c` 中 `hfdcan1.Init.AutoRetransmission = DISABLE`。向**不存在的 CAN ID**（0x02/0x03）发帧不会有人 ACK，每帧使 TEC +8，累计 >255 即 **BUS-OFF**，整条总线瘫痪。原探测阶段 20 帧 × 2 台未接 = 160，已接近临界；主循环再以 500Hz 持续打空帧 → 反复 BUS-OFF → 电机收不到任何帧 → 「没反应」/「转一会停」。
- 上一版能用的原因：那时三台全接在总线上，每个配置的 ID 都有应答，不存在空帧。
- 修复（已落地，编译通过 `Code=79738 / RO=19378 / ZI=39664`）：
  - `DM_PROBE_TRIES` 探测帧 20 → **5**。
  - 新增 `s_active[]`：探测不到的电机**之后完全不再发帧**。
  - 只对在线电机使能、周期补使能帧、故障清错重使能。
  - 新增在线看门狗 + 离线重探（`DM_REPROBE_MS = 3000`）：3s 内无反馈判离线并停发；离线电机每 3s 轻探 3 帧，接回来自动恢复并使能（力矩从 0 重新爬坡）。
  - 状态打印只列在线电机，末尾汇总未连接台数。
- 通用教训：**多电机固件里配置台数必须与实际接线一致，或代码必须跳过无应答的 ID**，否则空帧会把 CAN 控制器打进 BUS-OFF。

## 后续：力矩版"有声音、轴软、但不转"

- 对策（已落地，编译通过 `Code=79546 / RO=19354 / ZI=39496`）：
  - **`DM_MOTOR_NUM` 改为 1**（实际只接 1 台），`dm_cfg` 与 `dm_torque_init` 各留 1 项 —— 彻底消除向不存在 ID 发帧导致的 BUS-OFF。
  - 探测改为**最多 3 轮 × 5 帧**（原 5 帧一轮），避免上电头几帧丢失就判死。
  - 新增：一台都没探测到时长鸣 800ms，无串口也能判断"完全没通信"。
  - 节拍约定：响 1 声=力矩模式在跑；响 1 声后接长鸣=一台都没探测到；完全没声=旧固件。
- 待用户回报：**电机指示灯颜色**（绿常亮=已使能，红=未使能）——这是区分"没发使能帧"与"已使能但无转矩"的关键。

## 关键修复：Master ID=0 导致反馈永远匹配不上
- 深入排查后确认：`dm_motor_rx_dispatch()` 原来只比 `mst_id`。如果电机 Master ID 被设成 `0x00`（这台电机历史上正是这个坑），反馈帧会发到仲裁 ID `0x00`，永远匹配不上 → `online` 恒为 0 → 探测判离线 → **连使能帧都不发** → 轴软、完全不转、无任何转矩。与"有声音（固件在跑）、拧得动（kp=0）、但不转"完全吻合。
- 修复：`Bsp/dm_motor.c` 的 `dm_motor_rx_dispatch()` 改为三重兜底匹配：
  1) 仲裁 ID == `mst_id`（正常路径）
  2) 仲裁 ID == 电机自身 CAN ID
  3) 反馈数据 `data[0] & 0x0F` == 电机 CAN ID（达妙固定格式）
  任一命中即认。
- 同时把蜂鸣器改成完整自诊断协议：
  - **开机**：N 短 = 模式（1=力矩 / 2=锁定）
  - **探测后**：N 短 = 探测到 N 台；**长鸣 0.8s = 一台都没探测到**
  - 即「一短一短」= 正常，「一短一长」= 没通信
- 编译通过：`Code=79578 / RO=19354 / ZI=39496`。

## "5 次里 1 次能转一会停" —— 限速 + 彩灯仪表
- 新症状：加了 Master ID 兜底后，约 5 次上电有 1 次能转，但转一会就停。
- 分析：能通但不稳；"转一会停"最可能是**纯力矩（kd=0）没有速度上限**导致冲高。DM4310 在 24V 下接近最高转速时反电动势顶到母线，易触发过压保护（err=0x08）→ 掉使能停机。时序不同 → 表现为偶发。
- 改动（编译通过 `Code=79714 / RO=19346 / ZI=39496`）：
  - 新增限速阻尼 `DM_CTRL_TORQUE_VDES = 10.0f`（rad/s）、`DM_CTRL_TORQUE_KD = 0.5f`：kd>0 时用 `dm_set_mit(m,0,vdes,0,kd,tau)`，转速稳定在 VDES 附近不再冲高；填 0 退回纯力矩。
  - 新增**板载 WS2812 彩灯状态指示**（key_task 只在 init 时设一次绿色，故可安全覆盖）：蓝=探测中、绿=正常、红=有电机报错或离线；只在状态变化时刷写，每 2s 检查一次。
- 下一步判读表：绿+转=正常；绿+不转=力矩没出来；红+停=触发保护；红+完全不转=通信/使能问题。
- 仍需提醒用户：无串口只能靠灯和声音，接 USB-TTL 到 P6 才能看到 err 具体值。

## 自检轮播固件（DM_CTRL_MODE = 2）
- 背景：锁定模式（kp=20）能转、力矩模式（kp=0 / kd=0.5+v_des=10）复位后无反应，怀疑这颗固件对 `kp=0` 的帧不出力矩。
- 做法：新增自检模式，每 `DM_SELFTEST_PHASE_MS = 5000ms` 轮播一段控制律，换段前响 N 声，用户只需报告"第几声时电机动"：
  1. 响1声 纯力矩 `kp=0 kd=0 tau=1`
  2. 响2声 速度阻尼 `kp=0 kd=0.5 v_des=10 tau=1`
  3. 响3声 微刚度 `kp=0.13 kd=0.5 v_des=10 tau=1`（0.13 是 12 位编码下能表示的最小非零 kp，kp_uint=1）
  4. 响4声 位置保持 `kp=20 kd=2`（已知可用，作对照）
- 开机提示：自检版开机**长响 0.6 秒**，与正式版（短响）区分。
- 编译通过：`Code=79906 / RO=19346 / ZI=39504`。
- 判读：只有第4段动 → 固件确实不理 kp=0；第2/3段也动 → 之前是无速度上限的过速保护；四段都不动 → 帧根本没到电机（通信层）。

## 疑似电源被拉垮（重要线索）
- 自检实测：**第 2 段时电机"嗡"一声、没转，之后连蜂鸣器都不响了** → 典型的大电流导致电源跌压、单片机复位/停摆。
- 原因：第 2 段静息起步力矩 = `kd*(VDES-0) + tau = 0.5*10 + 1 = 6 N·m`，瞬时电流数安，小电源扛不住。
- 改动（编译通过 `Code≈79906`）：`DM_CTRL_TORQUE_VDES` 10→**3.0f**、`DM_CTRL_TORQUE_KD` 0.5→**0.2f**（起步仅 0.6 N·m，稳态约 8 rad/s）；自检每段 5s→**6s**；自检模式下探测提示音静音，节拍改为「长响0.6s = 自检版 → 每段前响 1/2/3/4 声」。
- **待确认的关键参数（一直没问过）：24V 电源的额定电流是多少？** DM4310 输出 1 N·m 约 1~2A，6 N·m 可到 6A 以上。若用的是 24V 2A 适配器，则一切时好时坏都能解释。

## 关键澄清：有声音的是电机本体，不是蜂鸣器
- 用户澄清：自检第 2 段时"**电机**发出声音"（不是主控板蜂鸣器）；改小参数后电机连声音都没了。
- 推论（重要）：**电机能发声 = 收到命令、在出力、电流在跟随指令**；声音随力矩变小而消失，说明 tau 项确实生效。**MIT 力矩通路是通的。**
- 因此真正的问题不是"力矩没出来"，而是"**力矩出来了但转不动**"。可能：① 顶到机械限位；② 负载太重（0.5~1 N·m 不够）；③ 电源撑不住一使劲就跌压。
- 新增正反转对照自检（`DM_CTRL_MODE=2`，每段 5s）：响1声=正向 `v_des=+3, tau=+0.5`；响2声=反向 `v_des=−3, tau=−0.5`。判读：两向都动=正常；只一向动=机械限位；两向只响不动=负载/电源。

## 空轴也不转 → 锁定 CAN Timeout = 0
- 用户确认：电机**空轴放在桌上**，仍然只嗡不转，两个方向都一样。
- 排除负载因素。结合"有嗡嗡声（在使能/抖动）但完全不出力矩"，锁定一个 10-14 就发现过、却一直没真正改掉的问题：
  **电机 CAN Timeout（RID 9）= 0**。社区文档（lerobot）明确记载该值的电机会"不响应命令"；我们读 0x02 那台时确实是 0，0x01 未确认，同批电机极可能都是 0。
- 失效机理：TIMEOUT=0 → 电机持续判通讯丢失、报 `err=0x0D(LOST_COMM)` → 旧固件每 2ms 就 clear_err+enable 一次 → 变成 500Hz 的"使能-报错-清错"抖动 → **嗡嗡响、零力矩、完全不转**，同时把真正的错误码盖住。
- 固件改动（已编译）：**删掉自动清错重使能**，改为把 `err` 码用蜂鸣器播报（响 N 声 = 错误码），并点红灯。0x0D 应听到 13 声。
- 修复动作：用 DMTool 在**上电待机态**（断电重启后不要发 `m`）把 **CAN Timeout 由 0 改为 20000**，写参数成功后断电重启。
- 错误码对照：0x08=8过压 / 0x09=9欠压 / 0x0A=10过流 / 0x0B=11 MOS过温 / 0x0C=12 线圈过温 / 0x0D=13 通讯丢失 / 0x0E=14 过载。

- 用户反馈（tau=0.1）：轴仍硬、松手回正、无抖动；"有点软、能拧动、拧时感到在发力"——与上一版手感一致 → **tau 未破坏位置环**，符合预期。
- 但 0.1 N·m 太小无法判断 tau 是否真被执行，遂把 `DM_CTRL_FF_TAU` 由 0.1 提到 **2.0f**（只改这一个数）。
- 预期可见效果：平衡点偏移 `2.0/20 = 0.1 rad ≈ 5.7°`，上电后轴会自己转约 6° 后停住；手推回原点、松手会再转回那个偏移点。
- 判读：① 转 6° 停住 = tau 通路确认、大小正确；② 完全不动 = tau 未被执行；③ 转了不停 = kp 太小或 tau 过大（需回调）。

## ✅ tau 通路确认（tau=2.0 实测）
- 用户反馈：**上电后先静默 1~2 秒，然后很快转到指定位置；到位后 3 号轴拧不动，2 号轴仍略可拧动。**
- 结论：`tau` 字段确实被执行，位置环 + 前馈同时工作正常。1~2 秒延迟属正常（启动+外设初始化+300ms 等待+60ms 探测）。
- 2 号与 3 号手感差异来自个体安装角度/背隙/负载，不影响结论。
- 下一步（只改一个数）：`DM_CTRL_HOLD_KP` 20→**0**，保持 `kd=2`、`tau=2`。
  力矩 = `2×(0−v) + 2` → 稳态 `v = tau/kd = 1 rad/s ≈ 9.5 rpm`，天然限速不会飞车。
- 调速方法：`kd` 越小越快（kd=1→2 rad/s，kd=0.5→4 rad/s）；`tau` 越大越有劲。

## 连续转动成功 + 速度差异的解释
- 拓扑问题确认：三台串在一个口上时末端（3 号）行为异常，**改为一台一个独立口后正常**——印证菊花链末端信号/电流问题，固件无关。
- 新现象：分开后 2 号电机比其它两台转得快。
- 解释：三台收到的是**完全相同的数据字节**（只有仲裁 ID 不同），固件不可能区别对待；稳态转速 `v = (tau − 负载阻力)/kd`，所以摩擦/负载小的转得快、大的转得慢，属正常个体差异。
- 为把速度降下来，`DM_CTRL_FF_TAU` 由 2.0 → **1.0f**（正好是用户最初要的 1 N·m），`kd` 保持 2 → 空载稳态 `v = 0.5 rad/s ≈ 4.8 rpm`，约 12 秒一圈。
- 关键公式（以后自己调）：**稳态转速 = (tau − 负载) ÷ kd**；kd 越大越慢，tau 越大越有劲。
- 编译通过，`MC02_firmware.hex` 156020 字节。

## 改为每台独立转矩（只有 2 号转）
- 现象：tau 统一 1.0 时，**只有 2 号恒速转动，1/3 号不转**；且开机时 2 号电机绿色指示灯亮得比另外两台慢。
- 解释：`v = (tau − 该台静摩擦)/kd`，tau 小于静摩擦则该台完全不转。之前 tau=2.0 时三台都有反应，降到 1.0 只剩最顺的那台 —— 与摩擦差异完全吻合。
- 固件改动：删掉全局 `DM_CTRL_FF_TAU`，主循环改用**每台独立的 `dm_torque_init[i]`**；默认 `{2.0, 1.0, 2.0}`（1、3 号阻力大给 2.0；2 号最顺给 1.0，也正是用户要的 1 N·m）。
- 灯亮得慢：判断为该电机上电自检/等待首个有效帧稍慢，不影响功能；且"亮得慢的那台恰好是唯一转起来的"，说明它对帧的响应更谨慎。
- 调法：哪台不转就把它那一位加到 3.0/4.0；哪台太快就往下减。上限 10 N·m，空载长时间大转矩会发热。

## 只有 2 号转：1、3 号静摩擦大于 2 N·m
- 实测 `{2.0, 1.0, 2.0}`：1、3 号表现为"位置不动"，2 号恒速转。由于 `kp=0`，1/3 并非真的锁位，而是**被静摩擦卡住**。
- 改为 `{3.0, 1.0, 3.0}`。
- 鉴别方法（无需固件）：`kp=0` 时静止的电机手能轻松拧动、无回正力；若拧着有回正力才说明 kp 不为 0。用这个区分"卡住"和"锁位"。
- 若 3.0 仍不动：可加到 5.0；但仍应手动确认 1、3 号轴是否明显比 2 号涩（减速箱/密封阻力），必要时断开负载验证。
- 电流提醒：1、3 各 3 N·m 合计约 6A，小电源会跌压。

## 换思路：tau 在三台上不一致 → 改用位置轨迹
- 实测序列：tau 统一 1.0 只有 2 号转；改每台 `{2.0,1.0,2.0}` 后 1、3 号不动；`{3.0,1.0,3.0}` 后 1、3 号变成"拧得动、拧完也不回"（= 完全无力）。
- 判断：**同一个 tau 编码值在三台电机上被换算成不同实际转矩**，最可能是三台内部 TMAX 参数不一致（kp 用的是固定 0~500 量程，与 TMAX 无关，所以在三台上都正常）。
- 结论：**放弃 tau 方案，改用位置轨迹**——只依赖 kp/kd（已证实在三台都有效）。
- 实现：目标位置每 2ms 前进 `SWEEP_SPEED × 0.002`，在 `起始位置 ± 4 rad` 之间来回摆；`kp=20, kd=2, tau=0`。
  - `DM_CTRL_SWEEP_SPEED = 0.8 rad/s`、`DM_CTRL_SWEEP_AMP = 4.0 rad`（±230°），单程约 5 秒。
  - 新增 `s_target[]`、`s_dir[]`，探测后以各自当前位置为起点，不会跳。
- 为什么不用"单向一直转"：输出量程仅 ±12.5 rad，单向转必然撞量程回绕，回绕瞬间目标跳 24 rad → kp×24 → 猛甩。来回摆在量程内绝对安全。若确需连续转，必须用反馈位置做增量式目标（每周期 target = 实际位置 + 步长），另做。
- 编译通过：`Code=79354 / RO=19206 / ZI=39656`。

## ✅ 位置轨迹方案验证通过（23:12）
- 用户反馈：烧录（未断电）后 **1、3 号正常恒速转 → 端点稍停 → 反转 → 循环**，正是设计的三角波来回摆；**2 号起初转很快，7~8 秒后自动与另外两台一致**；**断电重启后三台完全一致**。
- 结论：位置环 kp/kd 在三台上都正常，方案成立。之前 `tau` 表现不一致确认是各台 TMAX 换算差异（非通信问题）。
- "2 号起初异常快"解释：未断电烧录时电机仍保留上一次的速度/转矩指令，新程序接管后需数秒被新指令覆盖；**断电重启后即正常** → 以后改完固件应断电重启一次。
- 端点"停一小会"= 三角波到端瞬间反向，属于轨迹本身的特性；若要平滑无停顿，可把三角波换成正弦轨迹。
- 调速/调幅：`DM_CTRL_SWEEP_SPEED`（rad/s）、`DM_CTRL_SWEEP_AMP`（rad）；单程时间 = 2×AMP/SPEED。

## 扩展到 6 台（CAN1 三台 + CAN2 三台）
- 用户要求：另一侧三台挂主控板 **CAN2**，CAN ID `0x04/0x05/0x06`，Master ID `0x14/0x15/0x16`。
- `dm_motor.h`：`DM_MOTOR_NUM` 3 → **6**。
- `dm_ctrl_task.c`：`dm_cfg` 由 `uint16_t[N][2]` 改成结构体 `{hcan, id, mst_id}`，六项分别是
  `&hfdcan1 0x01/0x11`、`0x02/0x12`、`0x03/0x13`、`&hfdcan2 0x04/0x14`、`0x05/0x15`、`0x06/0x16`；
  `dm_motor_init()` 改用 `dm_cfg[i].hcan`。
- 新增 `s_amp[]`：摆幅按各自起始位置自动收窄（限制在 ±11.5 rad 内），避免撞 ±12.5 量程。
- 带宽：两条总线各 3 台 × 500Hz × 2（收发）≈ 各 33%，与单侧三台时一致，无需降频。
- 编译通过：`Code=79482 / RO=19242 / ZI=39928`。
- ⚠️ 前提：后三台必须先在 DMTool 里把 CAN ID / Master ID 改成 0x04/0x14、0x05/0x15、0x06/0x16；否则 CAN2 上发帧无人应答 → CAN2 BUS-OFF（只影响 CAN2，不影响 CAN1）。接线走板子「输出2」XT30，一台一个独立口。
